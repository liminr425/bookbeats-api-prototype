# BookBeats API Documentation (v1)

Base URL (local): `http://127.0.0.1:8000`

The main resource is **`playlists`**: a saved BookBeats playlist generated for a book (requirement FR-06).
All data is mocked in memory and resets when the server restarts.

## 1. Conventions

### Authentication
Protected endpoints need a mock token:

```http
Authorization: Bearer <token>
```

| Role | Token | Owner id | Permissions |
|---|---|---|---|
| Regular user A | `user-a-token` | `user-a` | Manages only own playlists |
| Regular user B | `user-b-token` | `user-b` | Manages only own playlists |
| Administrator | `admin-token` | `admin` | Reads, updates and deletes all playlists |

Public endpoints (no token): `GET /api/v1/greeting`, `GET /api/v1/health`.

### Response envelope
Success (`2xx`):
```json
{ "success": true, "message": "...", "data": { }, "meta": { "total": 2, "page": 1, "perPage": 10 } }
```
`data` is an object, an array, or `null` (delete). `meta` appears only on list responses.

Error (`4xx`/`5xx`):
```json
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [ { "field": "title", "message": "..." } ] } }
```
`details` appears only for validation errors. Error messages never contain stack traces, file paths or internal details.

### Error codes
| HTTP | `error.code` | When |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | Invalid/missing body fields, unknown fields, malformed JSON, bad query parameters |
| 401 | `UNAUTHORIZED` | Token missing, malformed or invalid |
| 403 | `FORBIDDEN` | Authenticated but not allowed (admin-only `ownerId` filter) |
| 404 | `NOT_FOUND` | Playlist (or route) does not exist, or the playlist belongs to another user |
| 405 | `METHOD_NOT_ALLOWED` | HTTP method not supported for the endpoint (response includes an `Allow` header) |
| 409 | `CONFLICT` | The same owner already has a playlist with that title |
| 500 | `INTERNAL_ERROR` | Unexpected server error (generic message only) |

### Order of checks
1. Authentication (401) → 2. Request validation (400) → 3. Existence and ownership (404) → 4. Conflict (409).

### Why 404 instead of 403 for another user's playlist
When a regular user requests a playlist that belongs to someone else, we return **404 Not Found**, the same response as for an ID that does not exist. With 403 an attacker could confirm that a given ID exists; with 404 they learn nothing. We still use 403 where it is accurate: a regular user using an admin-only feature (the `ownerId` filter).

## 2. Playlist object
| Field | Type | Notes |
|---|---|---|
| `id` | string | e.g. `pl_101`, generated by the server |
| `title` | string | 3-100 characters (trimmed), unique per owner (case-insensitive) |
| `bookTitle` | string | 1-150 characters |
| `bookAuthor` | string or null | optional, 1-100 characters |
| `mood` | string | one of `dark`, `tense`, `dreamy`, `nostalgic`, `calm`, `uplifting`, `romantic`, `mysterious`, `energetic` |
| `intensity` | integer | 0-100, optional, default `50` (the mood slider, FR-07) |
| `songs` | array | 1-20 items of `{ "title": string(1-120), "artist": string(1-120) }` |
| `ownerId` | string | set by the server from the token; read-only |
| `createdAt`, `updatedAt` | string | ISO 8601 UTC; read-only |

**Body rules (POST and PUT):** `title`, `bookTitle`, `mood`, `songs` are required. Fields are type-checked strictly (`"50"` is not an integer). Unknown fields, including `id` and `ownerId`, are rejected with 400.

## 3. Endpoints

### `GET /api/v1/playlists` - list playlists
- **Auth:** any valid token. Regular users get only their own playlists; admin gets all.
- **Query parameters:**

| Name | Type | Default | Rules |
|---|---|---|---|
| `page` | integer | 1 | >= 1 |
| `perPage` | integer | 10 | 1-50 |
| `mood` | string | - | one of the moods above |
| `q` | string | - | 1-100 chars; case-insensitive match on playlist title or book title |
| `ownerId` | string | - | **admin only**; filters by owner (403 for regular users) |

- **200:** `data` is an array, `meta` is `{ total, page, perPage }` (total counts all matches, not just this page).
- **Errors:** 400 (bad query parameter), 401, 403.

### `GET /api/v1/playlists/{id}` - get one playlist
- **Auth:** owner or admin. **Path:** `id` (string, e.g. `pl_101`).
- **200:** the playlist. **Errors:** 401, 404 (missing or someone else's).

Example:
```bash
curl http://127.0.0.1:8000/api/v1/playlists/pl_101 -H "Authorization: Bearer user-a-token"
```
```json
{
  "success": true,
  "message": "Playlist retrieved successfully.",
  "data": {
    "id": "pl_101", "title": "Gone Girl Nights", "bookTitle": "Gone Girl", "bookAuthor": "Gillian Flynn",
    "mood": "tense", "intensity": 80,
    "songs": [ { "title": "Everything In Its Right Place", "artist": "Radiohead" } ],
    "ownerId": "user-a", "createdAt": "2026-11-01T10:00:00Z", "updatedAt": "2026-11-01T10:00:00Z"
  }
}
```
(`songs` shortened here; the real response lists all songs.)

### `POST /api/v1/playlists` - create a playlist
- **Auth:** any valid token. **Headers:** `Authorization`, `Content-Type: application/json`.
- **Body:** see section 2. The owner is the authenticated user.
- **201:** the created playlist. **Errors:** 400, 401, 409.

Example:
```bash
curl -X POST http://127.0.0.1:8000/api/v1/playlists \
  -H "Authorization: Bearer user-a-token" -H "Content-Type: application/json" \
  -d '{"title":"Dune Focus","bookTitle":"Dune","mood":"mysterious","intensity":55,"songs":[{"title":"Time","artist":"Hans Zimmer"}]}'
```
Response `201 Created`: `"message": "Playlist created successfully."` with the new playlist in `data` (`"id": "pl_106"`, `"ownerId": "user-a"`).

Validation error example (`400`), body `{"title":"ab","mood":"angry","songs":[],"foo":1}`:
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request contains invalid or missing fields.",
    "details": [
      { "field": "title", "message": "String should have at least 3 characters" },
      { "field": "bookTitle", "message": "Field is required." },
      { "field": "mood", "message": "Input should be 'dark', 'tense', 'dreamy', 'nostalgic', 'calm', 'uplifting', 'romantic', 'mysterious' or 'energetic'" },
      { "field": "songs", "message": "List should have at least 1 item after validation, not 0" },
      { "field": "foo", "message": "Unknown field." }
    ]
  }
}
```

### `PUT /api/v1/playlists/{id}` - replace a playlist
- **Auth:** owner or admin. The body is a **full replacement** with the same rules as POST. `id`, `ownerId` and `createdAt` never change; `updatedAt` is refreshed. An admin editing a user's playlist does not take ownership of it.
- **200:** the updated playlist. **Errors:** 400, 401, 404, 409 (title already used by another playlist of the same owner).

### `DELETE /api/v1/playlists/{id}` - delete a playlist
- **Auth:** owner or admin.
- **200:** `{ "success": true, "message": "Playlist deleted successfully.", "data": null }`. **Errors:** 401, 404.

### `GET /api/v1/greeting` - HTML greeting page
Public. Returns `Content-Type: text/html; charset=utf-8`: project description, team, endpoint list, status and version. Responsive for desktop and mobile.

### `GET /api/v1/health` - health check
Public. `200` with `{ "success": true, "message": "BookBeats API is running.", "data": { "status": "ok", "version": "v1" } }`. Intended for UptimeRobot-style monitoring from the proposal.

### Error examples
| Situation | Status | `error.code` |
|---|---:|---|
| No `Authorization` header | 401 | `UNAUTHORIZED` |
| `Authorization: Bearer wrong` | 401 | `UNAUTHORIZED` |
| User A requests `pl_103` (owned by User B) | 404 | `NOT_FOUND` |
| Anyone requests `pl_999` | 404 | `NOT_FOUND` |
| User A calls `GET /playlists?ownerId=user-b` | 403 | `FORBIDDEN` |
| `PATCH /api/v1/playlists/pl_101` | 405 | `METHOD_NOT_ALLOWED` |
| POST a title the user already has | 409 | `CONFLICT` |
